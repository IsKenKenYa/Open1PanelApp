# API 适配执行计划

## 核心发现

探索发现「缺失」端点分三类：
1. **路径错误 bug**（6+9=15 处）：现有方法调用了错误 URL，会在真实服务器上 404 -- 最高优先级
2. **真正缺失的 REST 端点**（~27 处）：需要新增方法
3. **WebSocket 端点**（4 处）：不能作为 REST 添加，留后续

用户提供测试服务器（.env），可获取真实返回体验证端点正确性。

## 执行顺序

### 第一阶段：修复路径错误 bug（P0，15 处）
- ssh: `/settings/ssh/conn/default` -> `/settings/ssh/default`（ssh_v2 + setting_v2）
- monitor: `/hosts/monitor/gpu/search` -> `/ai/gpu/search`（monitor_v2）
- website: `/websites/log` -> `/websites/log/operate`（website_v2）
- website: `/websites/lbs?id=X` -> `/websites/X/lbs`（website_v2）
- host_tool: `/hosts/tool` -> `/hosts/tool/status`（host_tool_v2）
- host_tool: `/hosts/tool/config` -> `/hosts/tool/config/get` + `/config/set`（host_tool_v2）
- AI accounts: 9 处 `/ai/agents/accounts/*` -> `/ai/accounts/*`（ai_v2）
- 移除 5 个幽灵路径

### 第二阶段：新增缺失 REST 端点（~27 处）
- AI 模块 15 处（照搬前端）
- host/setting/ssh/monitor/website 12 处

### 第三阶段：验证
- flutter analyze + unit tests
- coverage check 确认 missing 下降
- 可选：用测试服务器验证真实返回体
