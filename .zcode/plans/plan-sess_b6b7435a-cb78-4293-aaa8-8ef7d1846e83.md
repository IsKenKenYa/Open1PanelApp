# 剩余端点最终清理计划

## 核心发现

探索发现 48 个"缺失"端点的真实分类：
- **18 个 ALREADY_COVERED**：已实现但在不同模块文件中，检查器正则匹配不到 -- 需更新检查器映射
- **4 个 WEBSOCKET**：WS 端点，不能作为 REST 添加 -- 已有 WS 客户端覆盖
- **3 个 PATH_VARIANT**：路径/方法不一致，需修正客户端路径
- **3 个 GHOST PATH**：调用了不存在的后端路由，需删除
- **12 个 AI DEFER**：TensorRT(商业版)/Hermes(需终端传输)/batch(不存在) -- 全部延后
- **4 个 TRULY_MISSING**：真正需要新增的 REST 端点

## 执行计划

### 第一步：删除 3 个幽灵路径
- `ai_v2.dart`: 移除 `getAgentBrowserConfig`(`/ai/agents/browser/get`)、`updateAgentBrowserConfig`(`/ai/agents/browser/update`)、`approveAgentFeishuPairing`(`/ai/agents/channel/feishu/approve`)、`testAgentModelConnection`(`/ai/agents/models/test`)
- 更新对应 alignment 测试移除这些端点

### 第二步：修复 3 个路径变体
- `container_v2.dart`: `downloadContainerLog` 从 GET 改为 POST（swagger 声明 POST）
- `backup_account_v2.dart`: `checkBackupConnection` 从 `/backups/check` 改为 `/backups/conn/check`
- `file_v2.dart`: `/files/read` 路径变体加入白名单（body-param 是有意设计）

### 第三步：新增 4 个真正缺失端点
- `setting_v2.dart`: `POST /core/settings/search/base`（基础系统设置信息）
- `website_v2.dart` 或 `setting_v2.dart`: `GET /settings/website/dir`（网站目录设置）
- `command_v2.dart`: `POST /core/commands/upload`（命令 CSV 上传）
- `cronjob_v2.dart`: `POST /alert/cronjob/list`（告警关联的计划任务列表）

### 第四步：更新覆盖率检查器映射
- `check_module_client_coverage.py`: 更新 `MODULE_CLIENT_FILES` 将跨模块文件加入对应模块
  - `process`: 加入 `file_v2.dart`, `host_tool_v2.dart`
  - `setting`: 加入 `ssl_v2.dart`
  - `ai`: 加入 `file_v2.dart`, `setting_v2.dart`
  - `group`: 加入 `host_v2.dart`, `website_v2.dart`
  - `ssh`: 加入 `setting_v2.dart`
- 更新 host legacy-fallback 识别（`_postWithLegacyFallback` 模式）

### 第五步：验证
- `flutter analyze`：0 error
- `dart run test/scripts/test_runner.dart unit`：全部通过
- `python3 check_module_client_coverage.py --all`：确认 aligned 模块数大幅提升

## 不做的事
- TensorRT LLM（5）：商业版 `isFxplay` 独有，移动端无模型管理 UI
- Hermes chat sessions（3）：需要交互式终端传输，端点单独添加无用
- Agent batch（4）：不存在于前端/后端/swagger
- settings/ai（4）：桌面终端/文件管理器 AI 助手配置，移动端无对应功能
- WebSocket 端点（4）：已有 WS 客户端覆盖
